RTK-хук переписывает `grep` в `rtk grep`, и тот отдаёт СВОДКУ («1 matches in 1 files»),
а не строки. Конвейер `grep -v X file > new && mv new file` затирает файл тремя
строками мусора. Так был уничтожен `MEMORY.md` 2026-10-02 (восстановлен из контекста
сессии; в git его нет — каталог памяти untracked).

**Why:** rtk-фильтр задуман для чтения человеком, не для машинной обработки.

**How to apply:** для правки файла по строкам не использовать grep вообще —
`sed -i '/X/d' file` или python. `rtk grep` только для чтения глазами.
Перед перезаписью любого файла из каталога памяти — копия, он вне git.
См. [[feedback_rtk_usage]].
