# Дизайн: Telegram-бот "Карьера"

**Дата:** 2026-05-25  
**Статус:** Approved  
**Проблема:** JobScanner → ResumePro → InterviewCoach не работает как pipeline. Агенты общаются через ненадёжный curl. Вакансии утекают, время идёт.  
**Решение:** Единый Telegram-бот "Карьера" как оркестратор — один источник правды, бот управляет всеми агентами, пользователь управляет всем из Telegram.

---

## 1. Архитектура — Бот-мозг (Approach A)

### Принцип

Бот "Карьера" — единственный оркестратор. Агенты не общаются друг с другом напрямую. Бот вызывает каждого через openclaw CLI с файлом-заданием, читает результат из стандартных директорий. Проблема межагентной коммуникации решается её устранением.

### Компоненты

```
JobScanner (cron 2x/день)
  └── пишет → ~/workspaces/jobsearch/reports/YYYY-MM-DD.md

ResumePro (вызов по заданию)
  ├── читает ← /tmp/career_task_<job_id>.json
  └── пишет → ~/workspaces/resume-editor/versions/<job_id>_draft.md

InterviewCoach (вызов по заданию)
  └── пишет → ~/workspaces/interview-coach/sessions/<job_id>_<date>.md

VBoris2 (vibe, вызов по заданию)
  └── навыки отклика по платформам

БОТ "Карьера" (smain, Python + aiogram 3.x)
  ├── pipeline.db — весь стейт
  ├── читает отчёты JobScanner
  ├── вызывает агентов через openclaw CLI
  └── общается с Борисом через Telegram API (через Lineman :9090)
```

### Вызов агентов

```bash
# Бот пишет задание:
/tmp/career_task_<job_id>.json  ← {job_id, jd_text, company, source_url}

# Запускает агента:
openclaw agent --agent resume-editor --task /tmp/career_task_<job_id>.json

# Агент пишет результат:
~/workspaces/resume-editor/versions/<job_id>_draft.md

# Бот polling'ом (каждые 30 сек, таймаут 30 мин) обнаруживает файл, читает, отправляет Борису
```

## 2. База данных — pipeline.db (SQLite)

```sql
-- Все найденные вакансии
jobs(
  id TEXT PRIMARY KEY,         -- hash(url + title)
  title TEXT,
  company TEXT,
  score INTEGER,               -- 0-100, скоринг JobScanner
  source TEXT,                 -- hh.ru, habr, @forchiefs, ...
  source_url TEXT,
  jd_text TEXT,                -- полный текст JD
  found_at DATETIME
)

-- Статус каждой вакансии в pipeline
pipeline(
  job_id TEXT PRIMARY KEY,
  status TEXT,                 -- см. стейт-машину ниже
  updated_at DATETIME,
  recruiter_name TEXT,
  recruiter_contact TEXT,      -- телефон / email / tg
  apply_platform TEXT,         -- hh / habr / tg / email / manual
  apply_confirmed_at DATETIME
)

-- Иммутабельный снапшот: точно то, что ушло работодателю
snapshots(
  job_id TEXT PRIMARY KEY,
  resume_text TEXT,            -- полный текст резюме — без сокращений
  cover_text TEXT,             -- полный текст письма — без сокращений
  approved_at DATETIME         -- момент нажатия "Отправить"
)

-- Сессии InterviewCoach
sessions(
  id INTEGER PRIMARY KEY,
  job_id TEXT,
  coach_session_path TEXT,     -- путь к файлу сессии
  started_at DATETIME
)
```

## 3. Стейт-машина вакансии

```
new           → найдена сканером, не показана Борису
  ↓ (автоматически при формировании дайджеста)
in_digest     → показана Борису в дайджесте
  ↓ (Борис нажал "В работу")
selected      → взята в работу, задача поставлена ResumePro
  ↓ (ResumePro записал draft)
draft_ready   → чистовик готов, ждёт согласования Бориса
  ↓ (Борис нажал "✅ Отправить")
  ↑ (Борис нажал "✏️ Правки" — возврат к selected)
approved      → согласовано, снапшот записан в DB, задача VBoris2
  ↓ (VBoris2 подтвердил отправку)
applied       → отклик отправлен, дата + платформа зафиксированы
  ↓ (VBoris2 поймал ответ работодателя)
response      → работодатель ответил, пуш Борису
  ↓ (Борис запустил подготовку)
interview_prep → InterviewCoach ведёт сессию
  ↓ (Борис закрыл вакансию)
closed        → оффер / отказ / снято, причина в архиве
```

Переходы `selected → draft_ready` могут повторяться при правках.  
Из любой стадии можно перейти в `closed`.

## 4. UX бота

### Главное меню (persistent keyboard)

```
[ 🔎 Дайджест ]    [ 📋 Мои отклики ]
[ 📄 Резюме в работе ]  [ 🎯 Интервью ]
```

### Поток 1: Дайджест

1. Борис нажимает "Дайджест" или говорит голосом
2. Бот читает последний `reports/YYYY-MM-DD.md`
3. Присылает вакансии порциями: сначала 🔥 горячие (score > 75), потом 📌 интересные (40-75)
4. Под каждой вакансией inline-кнопки: `[✅ В работу]` `[📋 Подробнее]` `[❌ Пропустить]`
5. При нажатии "В работу" — бот подтверждает голосом + ставит задачу ResumePro

### Поток 2: Резюме в работе / Согласование

**Push (бот сам пишет, когда ResumePro готов):**
> «ResumePro подготовил чистовик на [Роль] в [Компания]. Смотришь?»

**После нажатия "Посмотреть":**
1. Бот присылает полный текст резюме (без сокращений)
2. Бот присылает полный текст сопроводительного письма (без сокращений)
3. Кнопки: `[✅ Отправить]` `[✏️ Правки]` `[❌ Отложить]`

**При "✏️ Правки":** Борис пишет/говорит правки → бот пересылает ResumePro → новый draft → снова согласование.

**При "✅ Отправить":**
- Снапшот (resume_text + cover_text) записывается в DB иммутабельно
- Бот вызывает VBoris2 с нужным навыком платформы
- После подтверждения: пуш «Откликнулся на [платформа]»

### Поток 3: Браузер откликов

Команда "Мои отклики" → список карточек, отсортированных по приоритету:
1. 🔴 `response` — работодатель ответил (вверху)
2. 🔵 `draft_ready` — ждёт согласования
3. 🟠 `applied` — ждём ответа
4. 🟡 `approved` — в процессе отправки

**Карточка вакансии содержит:**
- Название, компания, дата отклика, платформа
- Контакт рекрутёра (если есть)
- Кнопки: `[📝 Полное резюме]` `[✉️ Полное письмо]` — дословный текст что ушёл

**Из карточки со статусом `response`:**
- Кнопка `[🎯 Подготовиться к интервью]` → запускает InterviewCoach

**Назначение браузера:** когда звонит рекрутёр и говорит "вы тут пишете...", Борис открывает карточку и видит каждое слово которое было отправлено.

### Поток 4: Интервью

1. "Интервью" или из карточки отклика
2. Список вакансий со статусом `response` / `interview_prep`
3. Борис выбирает → кнопки: `[🏢 Разведка компании]` `[🗣 Mock-интервью]` `[❓ Разобрать вопрос]`
4. Голосовой ввод ответов на вопросы
5. InterviewCoach даёт фидбек после каждого ответа

## 5. VBoris2 — навыки отклика

Файлы в `~/workspaces/career-bot/apply_skills/`:

| Файл | Платформа | Метод |
|------|-----------|-------|
| `hh_apply.py` | hh.ru | API + форма, загрузка DOCX |
| `habr_apply.py` | habr.career | браузер (Playwright) |
| `tg_apply.py` | Telegram-канал | личка рекрутёру, шаблон |
| `email_apply.py` | Email | SMTP, вложение PDF/DOCX |
| `getmatch_apply.py` | getmatch.ru | браузер |
| `generic_apply.py` | прямой контакт | выдаёт инструкцию Борису |

Credentials — через Keymaster по ключу `APPLY_<PLATFORM>_CREDS`.  
VBoris2 выбирает навык по полю `source` в задании.  
После успеха — возвращает подтверждение + ссылку/скриншот боту.

## 7. Голос

- **Mini-app** (кнопка в боте) — полноценный голосовой чат. Скопировано из Nurse, минимальные правки (токен, agent_id, маршрут на Portal).
- **Голосовые в боте** — только по явному запросу: «Вышли голосовое о том-то» → `tts_flow.py` → OGG.
- **Голосовой ввод** — любое .ogg → `parse_voice.py` → текст → обработка.
- **Push-уведомления** — всегда текст.
- **TTS-профиль** — новый голос "Карьера" (деловой, уверенный), настраивается через voice wizard.

## 8. Что создаём / меняем

### Новое
- `~/workspaces/career-bot/` — Python-сервис (aiogram 3.x) + pipeline.db
- `~/workspaces/career-bot/apply_skills/` — навыки VBoris2 по платформам
- `~/.config/systemd/user/career-bot.service` — systemd unit
- Маршрут `/career` на Shectory Portal (mini-app, копия из Nurse)

### Минимальные правки к агентам
JobScanner, ResumePro, InterviewCoach — добавить поддержку файлового задания:
- читать `/tmp/career_task_<job_id>.json` при запуске с флагом `--task`
- писать результат в стандартную директорию (`versions/`, `sessions/`)
- AGENTS.md агентов не трогаем

### Без изменений
- Cron JobScanner — работает как есть
- Голосовая инфраструктура (`parse_voice.py`, `tts_flow.py`) — переиспользуется
- Federation / Lineman / Keymaster — без изменений
